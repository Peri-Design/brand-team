# PixVerse 品牌工作台

线上版本已部署至 https://brand-team-production.up.railway.app/ 。本地开发可双击 `启动工作台.command`，保持启动窗口开启，在浏览器使用 http://127.0.0.1:8766/ 。

## 使用

首次在当前浏览器进入「设计编辑」时，会显示可跳过的三步指引。完成、跳过或关闭后不再自动弹出；顶部「使用帮助」可随时查阅三步说明，并重新查看指引。公开品牌素材页不显示编辑指引。

1. 上传 PNG / JPG / WebP 主视觉，自动生成补边色和 Web 色块初始配色；选择 Web、App 资源位及中日英语言。
2. 分别填写所选语言的文案；不自动翻译。App 使用「双行大标题」时，Web 与 App 共用双行标题；切换到「主标题＋副标题」后，Web 两行标题与 App 单行主标题、单行副标题分别编辑并各自保存。
3. 资源位、语言、图片和文案变化会实时更新右侧画布；可继续调整某一张的图片缩放、位置和补边渐变。
4. 需要统一构图时，点击画布上方「批量调整」，勾选同一资源位的图片，将当前基准图的缩放与位置同步到所选图片。可选「同时同步左侧渐变」；退出后仍可单独调整某一张。Web 与 App 不可交叉选择。
5. Web 与 App 需要不同图片时，在右侧「资源位图片」替换当前资源位图片。独立图片同步该资源位的中、英、日三张卡片，不跨资源位；仍可逐张微调构图。上传后该资源位缩放与位置恢复为 100% / 0 / 0，保留渐变宽度；「恢复使用母版图」可一键回退。
6. 在「资源位与版式 > Web 首页 Banner > 模板色块」使用「自动匹配主视觉」或「自定义」；自动匹配后可修改两层色块的渐变色和不透明度。该设置同步到所有 Web 语言，不影响 App。形状来自现有 Figma 原始矢量路径。
7. 点击顶部「选择下载」进入下载选择，默认全选当前结果；可跨 Web、App 和语言任意勾选。选择一张时下载 PNG，选择多张时下载 ZIP。下载选择只决定导出范围，不同步构图或其他参数；「批量调整」仍只允许同一资源位。
8. 「新建设计」会立即创建云端文件，后续修改自动保存到云端；「文件」只展示当前飞书账号有权访问的云端文件。本机仅保留不可见的恢复缓存，不作为独立文件展示。同步失败时页面会显示「有未同步修改」，可点击「重试同步」。

「活动文字颜色」默认纯白 `#FFFFFF`，支持自定义取色或输入 6 位 HEX 色值，仅应用于当前选中的一张设计的主副标题，随云端文件保存，支持撤销／重做。仅保留「纯白」和「自定义颜色」；旧工程的模板原色设置迁移为默认白色。实际导出、刷新回读及颜色校验见 [验证记录](验证/2026-09-24_自定义文字颜色/验证记录.json)。

## 界面图标规范

- 界面功能图标统一维护在 `dist/index.html` 的 SVG symbol 集合中，通过 `<use href="#i-*">` 引用；不使用 Unicode 箭头、叉号、加减号或页面内临时绘制的 SVG 代替。
- 所有图标采用 `24 × 24` viewBox、无填充描边、`currentColor`、圆角端点与圆角连接；全站线宽由 `--icon-stroke: 1.75` 统一控制。包含矩形边框时统一使用 `rx="2"`，不混用尖角框和不同半径的圆角框。
- 视觉尺寸固定为三档：侧栏导航 `22 px`、常规操作 `18 px`、紧凑工具和下载操作 `16 px`。同一行、同一层级的图标必须使用同一尺寸档位。
- Logo、品牌 Icon、素材预览和状态插画属于内容资产，不套用界面功能图标规则。
- 新增图标时先加入共享 symbol，再引用现有尺寸档位，并运行 `验证/icon-system.test.cjs`，避免局部图标的线宽、大小或绘制方式偏离全站规范。

自动配色在本机分析原图左侧的主要颜色，生成补边色和两层同色系 Web 渐变；会过滤少量亮点，并参考当前文字的明暗。仅作为初值，不承诺识别所有主体或保证复杂背景的衔接。首次示例、替换主视觉时计算；刷新、打开当前工程不会重新覆盖已保存配色。两处各有重新匹配按钮，手动调整会保留。Web 色块仅保留「自动匹配主视觉」和「自定义」；旧工程中的「礼盒紫色」「规范原配色」会按工程主视觉重新自动匹配。自动匹配不打开补色开关，不改变色块形状、透明度、字体及构图。全透明图保留已有颜色并提示手动选色。

## 尺寸与保真

工作台布局：桌面端左侧设置、中间预览、右侧单张调整独立滚动，顶部工具栏保持可见。主视觉、语言文案默认展开；资源位与版式、Logo、色块默认收起并显示配置摘要。701–1100 px 窄窗口通过「单张调整」展开侧面板；700 px 及以下使用纵向页面。画布底部提供 10%–400% 观看缩放、适应窗口（按宽度）、查看全部（全部画板适应可视区域）和放大选中（选中画板居中）。画板按资源位分行、按已选语言分列（中文、English、日本語）；选一种语言一列、两种两列、三种三列，窄窗口保留排列。资源位或语言的勾选变化会立即增删对应画板，无需手动更新预览。每张卡片也有「放大查看」。100% 对应模板规范的 1× 显示尺寸，PNG 始终按 4× 输出。超过窗口时可横向、纵向滚动；画布区域内 Ctrl/⌘＋滚轮可缩放，聚焦浏览区域后可用 +/−、0（适应窗口）。支持拖动空白处平移、空格临时平移、手型模式在图片上平移；输入文案时空格正常输入。查看全部可找回画板。观看状态不写入工程或撤销历史，刷新恢复适应窗口。预览按缩放和屏幕像素密度从原素材重绘（4×–8×），DOM 使用布局缩放；导出仍单独按规定 4× 绘制。右侧「主视觉缩放」仍用于修改构图。

- Web 使用 330 × 139.5 的 1× 坐标；PNG 输出 1320 × 558。

- 自动适配使用主体靠右、左侧放文字的规则，不包含主体识别。导出前仍需人工检查构图、清晰度和对比度。

- Web 标题每行位置已按 2026-09-28 Figma 最终节点配置；浏览器与 Figma 的字体光栅化仍可能有不超过数个输出像素的抗锯齿差异。
- 文案同步按版式结构决定：App「双行大标题」与 Web 共用标题；App「主标题＋副标题」使用独立主副标题，修改 Web 不影响 App，切回双行版式会恢复共用标题。旧工程首次打开时，中文、日文通过去除换行、英文通过换行改空格生成 App 单行标题初值；初值过长时只提示缩短，不改变模板字号。异常多行数据只绘制允许的第一行并阻止导出，不会覆盖副标题。Web 双行标题、App 双行标题和 App 主副标题均按每一行当前字形的实际左边界进行视觉对齐，各自保留模板锚点，不使用语言固定偏移；开头标点和显式空格保留原排版。

## 云端文件与权限

品牌素材浏览与下载保持公开，不要求登录。新建设计、编辑和文件管理需要飞书登录并通过管理员审核；普通成员只能读取、保存和删除自己的云端文件。云端文件使用版本号阻止多个页面互相覆盖。`FEISHU_BOOTSTRAP_ADMIN_NAME=赵瑞秀` 只在首次匹配登录时使用，成功后管理员权限绑定到该飞书账号的 `open_id`，同名账号不会继承权限。管理员概览只展示用户数、文件数、归属和存储量，不读取其他成员的设计内容。

「新建设计」始终创建不含主视觉、文案和预览结果的空白云端文件，不继承当前文件或内置示例。没有任何云端文件的新用户第一次新建时，会看到一次项目1示例引导；示例只用于说明操作和最终效果，不写入文件数据，也不出现在文件列表中。创建操作带防重复锁，同一次点击只会创建一个文件；未同步的恢复副本会先要求重试同步，避免被新文件覆盖。打开已有文件只读取并绑定该文件，不触发新建；切换文件前会先完成当前文件的自动同步，只有同步失败且仍有未保存修改时才显示风险确认。编辑页 URL 会携带文件 ID，刷新后仍打开同一个文件。编辑已有文件时左侧保持“文件”选中，“新建设计”只作为创建动作。

服务端需要 Node.js、PostgreSQL 和以下环境变量：`PUBLIC_URL`、`DATABASE_URL`、`SESSION_SECRET`、`FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_BOOTSTRAP_ADMIN_NAME`。参考 `.env.example`。在飞书开放平台中，需要创建企业自建应用，将 `${PUBLIC_URL}/api/auth/feishu/callback` 加入重定向 URL，并发布到允许使用的成员范围。

当前浏览器会保留一份不可见的恢复缓存，用于网络或同步异常时保护未同步修改；它不出现在文件列表中，也不作为日常文件入口。同步恢复后，修改会写回对应云端文件；没有对应云端文件时会创建新的云端文件。图片仍在浏览器生成和导出，云端保存现有文件数据。公共模板更新须更新 `dist` 中的配置和资产并重新部署；不会自动覆盖已保存文件的活动颜色。暂不提供多人实时共同编辑、模板在线发布、AI 扩图或 PixVerse 调用。

图片上传限制为 40 MB、5000 万像素；浏览器可用内存会影响处理速度。

## 设计权限申请通知（v1.8.9）

成功完成飞书登录且状态为待审核的成员，会进入服务端通知队列。服务器使用现有应用凭据，向数据库中已绑定的管理员 open ID 发送飞书消息，包含申请人姓名和 `/?view=admin` 审核入口；不依据同名联系人寻找收件人，不自动批准权限。首次上线会补发仍待审核的申请。

通知记录保存在 `access_notifications`，按申请人和管理员去重；每分钟检查一次，发送失败按 2 分钟至 1 小时退避重试，进程重启后继续。发送采用固定消息 UUID，降低网络重试的重复消息风险。飞书的消息去重存在时限，远端成功但本地记录失败的极端情况仍可能重复收到提醒。已批准或停用的成员不再发送积压通知。通知失败不影响登录、申请记录和后台审批。

部署前提：飞书应用需启用「机器人」，并发布 `im:message:send_as_bot`（以应用的身份发消息）权限，管理员需在应用可用范围内。`PUBLIC_URL` 为工作台正式地址；无需添加新的接收人密钥。飞书应用可用范围与工作台的设计审批互相独立，范围外成员无法完成登录，也不会产生工作台申请。2026-10-10 实际查询生产应用返回 `11205 / app do not have bot`，机器人能力待应用管理员开通；不可宣称消息已送达。
